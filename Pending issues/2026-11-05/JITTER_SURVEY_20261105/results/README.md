# 隔帧停顿（held-frame / on twos）全量只读普查结果（2026-11-05）

算法与 `Pending issues/2026-11-05/JITTER_484746C4_20261105/scripts/cadence.py` 相同（`held_frames.py` 用 ffmpeg `tblend` + `signalstats` 重写，逐项对齐该脚本）：264×152 灰度、逐帧平均绝对差切成步长 6 / 长 12 的窗，跳过切镜与静止窗，窗口内**偶数帧均值 / 奇数帧均值 < 0.35** 判为「一拍二」，`held_share = held / moving`。

## 运行方式

在 **web 容器**内跑（脚本头部的命令），只读：`group_current_videos` 的 SELECT + MinIO GET，逐条下载到临时文件后立即删除；无写库、无写对象、无 Provider 调用、不触发重生成。

```bash
docker compose cp /home/edy/jitter_survey_20261105 web:/tmp/jitter_survey
docker exec -e OUT=/tmp/jitter_out -e LIMIT=4500 -e SINCE=2026-10-01 \
    tubeflowai-test-web-1 sh -c 'nice -n 19 python /tmp/jitter_survey/jitter_survey.py'
docker compose cp web:/tmp/jitter_out /home/edy/jitter_out_20261105
```

- `SINCE=2026-10-01`（默认值）；`LIMIT=4500`：**刻意放大**——脚本默认 400 只会取最新 10%，本次按用户要求跑全量，启动前基数为 4182，`LIMIT` 高于基数故未截断。
- 2026-11-05T15:05:51Z 启动、15:29:47Z 结束，**24 分钟**（单条约 0.34 s）。
- 部署后 60 分钟观察窗结束才开始，避免 CPU 争用污染线程池超时观察；`nice -n 19`，期间 `/health/live` 持续 200。
