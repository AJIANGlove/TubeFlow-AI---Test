# ========== b) 用 projects 的 xmin 推断创建时间（07:03:53Z / 07:04:06Z）==========
说明：xmin 是 xid 类型，比较与聚合需 ::text::bigint；age(xmin) 才是可比的"年龄"。

  select count(*), max(age(xmin)), min(age(xmin)) from projects;

  -- 目标 schema
  select age(xmin) from pg_namespace where nspname='contract_be30c85aac3347ffbf3bc45bc6ea12de';

  -- projects 中 age 小于 51673862 的最大 3 个（= 比它更晚的行）
  -> d80b2be7-8c9c-4d54-b438-0016788e6dec | 2026-09-04 16:00:18.049882+00 | 48580910
     b497a6b5-e594-42b8-8d92-2e390f0d7161 | 2026-09-04 16:00:18.049882+00 | 47864396
     456c0fad-49c9-4287-a3aa-4c50fa5ee655 | 2026-09-18 13:31:52.030474+00 | 44591097

  -- age 大于 51673862 的行
  -> (0 行)

结论：目标 schema 的 age 大于**全部** 62 个项目行 => 它比最早的项目行（2026-09-04T16:00:18Z）
      还早，无法用相邻项目夹出区间，只能给出上界：**早于 2026-09-04T16:00:18Z**。
      与最早项目相差约 3,092,952 个事务（51,673,862 − 48,580,910）。

局限（必须与结论一起读）：
  1) xid 是 32 位，可能回卷（本集群 age 约 5,170 万，尚未接近 2^31，暂不构成问题）；
  2) 并发事务下 xid 顺序与提交时间不严格单调；
  3) projects.xmin 是该行**最后一次修改**的事务号，不是创建时间；
  4) pg_namespace 行的 xmin 在 ALTER SCHEMA（如改属主）后会被更新，届时反映的是那次修改。

旁证（仅假设，未验证）：三个 audit 类 schema 名字里带 20260829，且 alembic_version 为 0006/0007，
与"2026-08-29 前后的迁移/审计快照"一致；但这一点来自命名，不能作为时间证据。
