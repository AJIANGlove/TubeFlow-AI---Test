## 2. 发现与分析

- **遗留的 `contract_be30c85aac3347ffbf3bc45bc6ea12de` 位于业务库 `tubeflow`**，所在容器为 `tubeflowai-test-postgres-1`。测试库 `tubeflowtest` 在另一个 Postgres 容器 `tubeflow-contract-pg` 中。
- 只有集成测试夹具会建 `contract_` 前缀的 schema（`conftest.py` 与 `test_project_director_v4_migration.py`），所以**某次集成测试曾指向业务库**。
- 仓库中留有记录的集成测试运行都指向测试库：2026-11-04 用 `postgres@…:55433/tubeflowtest`，2026-11-06 用 `postgres@…:55435/tubeflowtest`。出事的那次运行没有记录。
- 该 schema 是空的，说明那次在迁移阶段就失败了，没有写入测试数据，业务数据也未受影响。但迁移成功的运行会在结束时删除自己的 schema、不留痕迹，所以**不能排除别的时候也有过指向业务库的运行**。
- 实施方在 FINAL_ACCEPTANCE §48 中写「测试库 0 行，夹具修复生效」，这一推论不成立：本轮没有迁移失败，用旧夹具的 main 一侧同样是 0 行。已更正。
