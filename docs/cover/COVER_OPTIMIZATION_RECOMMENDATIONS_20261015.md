# 封面生成优化建议清单（2026-10-15）

已把外部两个方案、已查证的事故根因、代码现状和 `USER_DECISIONS.md` §18 的已确认边界全部对齐。以下逐项列出：**类别 A = 不与已确认决策冲突，可直接做；类别 B = 触及已确认决策或新增模型调用，需你先决策**。

---

**1. 存量频道风格档案修复（本次事故的直接根因之一）— 类别 A**
- 位置：`cover_style_profiles` 版本 1（频道 05f1dfa1）；机制在 `splice_ref_children`/`assemble_prompt_body`（domain/cover.py:636, 959）。
- 为什么：备份库证实该档案是 v4 时期**全选 8 维**解析的产物，空间/构图/色彩行是对一张旧图（湖畔露营场景）的逐字复述，且逐字钉进每个封面——图3 的湖/山/黄帐篷/篝火构图即来源于此。v5 计划已自认此问题（"原全选 8 维为误导性默认，E2E 实测全选=全量复刻"）并把默认勾选收敛为 `["style","composition"]`，但**存量档案未修复**；你当前项目草稿又是"已选 36/36 子项"。
- 怎么优化：用现有功能（无需新代码）对该参考图按"纯风格"勾选（style+composition）重新解析 → 固化为新版本风格档案 → 切频道当前指针；旧版本保留可回切。项目草稿勾选同样收敛。
- 预期效果：新封面的场景/光影/色彩不再被旧图冻结，改由标题+文案驱动；风格行仍逐字锁定。这是本次所有优化中**成本最低、收益最直接**的一项。

**2. 角色卡画风与频道风格的冲突裁决 — 类别 B（触及 v5 §1.2 已确认内容）**
- 位置：角色卡解析任务单 `_CHARACTER_CARD_ANALYSIS_USER`（domain/cover.py:1214，要求提取"画风"）；绑定规则 `bind_character_cards`（:1313）。
- 为什么：备份库证实角色卡外貌文本以"**三维卡通写实风格**"开头，绑定时逐字替换参考图的人物身份/外貌，与逐字进入成品的风格行"平面化卡通、粗黑描边、平涂色块"**同现于同一提示词且无任何优先级裁决**；图3 跟随了角色卡画风。
- 怎么优化（三选一，需你定）：a) 角色卡解析不再提取"画风"，只保留身份/头身比/面部特征/标志性元素，画风由频道风格唯一供给（改 v5 §1.2 确认内容）；b) 绑定生效且风格档案含 style 维度时，面板提示"角色卡画风与频道风格冲突"，由你选择优先级；c) 最小改动：在【角色绑定】system 段（domain/cover.py:1223）追加裁决句"角色的渲染风格服从风格维度的既定描述"。
- 预期效果：消除"三维写实 vs 平涂卡通"的矛盾输入；角色形象在频道画风内保持识别度而非自带画风。

**3. 质量锚点与风格目标解耦 — 类别 B（轻决策：§11.6 确认过"恒定追加不让步"）**
- 位置：`QUALITY_ANCHOR` 与 `assemble_prompt_body`（domain/cover.py:264, 976-977）。
- 为什么："细节丰富，构图清晰有层次，主体突出，高清晰度"恒定追加，对"简笔/平涂"类风格是反向引导，与风格行直接打架。
- 怎么优化：锚点按风格语义适配——风格档案含"平涂/简笔/卡通"语义时改用"线条干净、色块平整、边缘清晰、主体突出"类锚点；或把质量句降为随风格档案存储的可配置字段。
- 预期效果：不再把模型推向精致渲染，与风格行同向发力。

**4. 封面文字任务单流程化（Claude 方案的核心）— 类别 A**
- 位置：`_COVER_TEXT_SYSTEM`（domain/cover.py:295）。
- 为什么：现任务单只有抽象原则（"好奇缺口""情绪优先"）无推理步骤——Claude 对话指出这正是"结论而非操作方法"，AI 拿到只会给泛泛结果。§18.10 确认的合同（5 候选、≤30 码点校验、回退）不需要变。
- 怎么优化：任务单内加显式步骤：①列 3 组"观众默认认知 × 视频情境"反差对 → ②写出观众脑子里冒出的疑问句 → ③压缩成封面词；增补三条规则："不写画面能表达的信息（与画面/标题补位而非重复）""优先具体名词/数字，少用形容词""结尾用？或？！"；把"2–6 个词"收紧为"优先 1–3 个词"（校验上限不变）。
- 预期效果：封面文字从"按原则采样"变为"按可检验步骤推导"，钩子命中率提升，且质量对模型波动的敏感度下降。

**5. 画面任务单补充可检验构图规则 — 类别 A**
- 位置：`_COVER_PROMPT_SYSTEM_HEAD` 画面要求段（domain/cover.py:343）。
- 为什么：现有"主体突出"过于抽象；参考图（图2）的核心特征——瞪眼、抱头、旁人惊恐——没有任何确定性约束，完全靠 LLM 自由发挥。
- 怎么优化：补入两条确定性规则："主角有明确表情，且至少一个旁观者给出夸张反应（替观众先惊讶）""可放 1–2 个暗示答案的小道具，但不解释、不画结果"。
- 预期效果：画面情绪强度与"夸张表情"这一风格要素得到稳定兑现。

**6. 评审环节升级：评委观众模拟 + 出图后视觉复审 — 6①类别 A / 6②类别 B**
- 位置：评委任务单 `_JUDGE_SYSTEM`（domain/cover.py:363）；出图链 `cover_images.py:169-175` + `cover_image_qc.py`。
- 为什么：①现评委是 7 维抽象 rubric 打分，没有"观众第一反应"锚点；②出图 QC 实测只查解码/尺寸/格式/哈希，**出图后无任何对图像内容的评审**——图3 这种风格全错、内容全对的图能顺利通过全部闸门。Claude 工作流的第 3 步恰恰是"看图评审"。
- 怎么优化：①评委任务单加入"0.5 秒观众三问"（读到了什么字/冒出什么问题/想不想点进去）作为各维打分的锚定问题（纯文本改动）；②新增出图后视觉复审环：复用既有视觉通道（grsai，cover_ref_analysis.py 同构）对封面图出结构化问题清单（文字拼写、风格符合度、文字可读性、小图可读性），**只呈现不自动重提**，由你决定重生成——新调用需授权口径与验收条款。
- 预期效果：文本评分更贴近点击行为；风格跑偏/绘字错误在交付前多一道拦截闸。

**7. 风格解析输出形态：整图复述 → 抽象化关键词 — 类别 B（改解析输出合同，需同步 §18.3/§18.6 文档）**
- 位置：`build_ref_analysis_messages`（domain/cover.py:467）；装配 `assemble_prompt_body`。
- 为什么：两个外部方案的风格写法都是 4–8 个关键词（"thick clean black outlines, flat and bold colors"/"简笔卡通、粗黑描边、平涂色、表情夸张"）；我方解析是 36 子项自然语言长句，风格行在成品中被几十个场景名词淹没（备份真实 prompt 证实），且 composition 等"纯风格"维度的子项文本仍可携带场景内容（如"左下角横向躺卧"）。
- 怎么优化：解析任务单对纯风格维度（style/composition）要求"跨场景可迁移的抽象短句/关键词串"（可中英双语），禁止复述具体场景元素；装配时风格行前置或独立成段。
- 预期效果：风格信号在成品提示词中权重上升、不被场景细节稀释；与第 1 项互为表里（1 治存量，7 治增量）。

**8. 英文生图提示词（双语）— 类别 B（需先小实验，如实标注无本项目实测）**

- 预期效果：不确定，需实验确认——如实说明，不先验承诺。

**9. 垫图/图生图（方案 D）— 类别 B（§18.3 已确认"参考图只以文本进入"，§18.11⑦ 已定"实测前单独报批"）**

**10. 绘字段 → 无字底图 + 本地确定性绘字 — 类别 B（与 §18.10 已确认决策直接相反）**
- 位置：`COVER_TEXT_FIELD_TEMPLATE`（domain/cover.py:267）与 `assemble_final_prompt`。
- 为什么：两个外部方案一致建议"no text 底图 + 后期加字"；但你在 §18.10 已明确确认"封面图需要文字、绘字段逐字拼入、不做 OCR 校验以评委软约束兜底"——**这是已确认决策，我只能把利弊摆给你重新决策**：改成本地合成（Pillow/ffmpeg 文字层，频道级字体/亮黄填充/黑描边/位置参数化）后，文字样式一致性不再依赖模型、绘字错误整类消除；代价是放弃模型绘字的排版多样性，需要新合成组件与验收，且与"文字与画面互相强化"的设计耦合方式改变。折中路径：维持模型绘字，先上第 6② 项视觉复审来发现绘字错误（注意 §18.10 "不做 OCR 自动校验"的口径，视觉复审是否算 OCR 校验需你认可）。
- 预期效果：若采纳，封面文字（样式、拼写、位置）成为确定性产物；风格一致性中"标题字样式"这一半彻底脱离模型发挥。
