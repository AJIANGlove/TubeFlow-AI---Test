> （1671×941，3 格，格内印 `SHOT n`）+ 提示词 `/tmp/prompt_g2_pix.txt`（4203 字符）+
> 同一角色图；seed `123456789`、294 帧、基线 1056×608，每臂约 3.5 分钟。
> 判读：1fps 拼图 + 第 7 秒整帧人工看，再用同一套几何检测器交叉验证。

## 0. 结论

1. **只有 K 臂干净**：单格参考 + 单镜提示词，得到一条连续镜头，无格线、无标签、无信息图叠加。
2. **参考图侧的微调全部无效**：去 caption（B）、去格线（D）、改提示词（E）、换 seed（F）、
   原尺寸参考（G）、模糊（G2）、降采样（G3）、关 strict（H）——都仍然同框，只是失败形态在变。
3. **文字和格线都不是必要条件**：B 去掉标签仍有三格；D 去掉格线，模型自己把接缝和标签补回来。
4. **同框与格子数量无关**：存量 144 个泄漏组里 86 组是 2 格分屏，24 组才是 3 格；
   所以"把 3 格改成 2 格"也不会解决。
5. **新失败形态**：C / F1 / I1 消掉了同框，但把价格图或素材图**合成成浮层压在实拍上**；
   现有检测器查不到这一类，验收若只看"有无同框"会误判通过。
6. 根因层级：**整张多格参考图被模型当作一帧构图**。这不是提示词、caption 或格线能修的，
   必须改"参考范式"。

## 3. 检测器在这批臂上的表现

- 命中：A、E、G、G2、H（深色格线 + 规则位置）。
- 表中 B、F2 显示 `suspect`，是原始评分规则（要求 ≥2 帧）；按存量普查采用的规则 v2（单帧同时命中 1/3+2/3 即判 `leak`）二者都是 `leak`。
- **漏判**：D、F3、G3（接缝是浅色或明暗过渡，不是暗线）——三者人工看都是同框。
- 正确放行：C、F1、I1（确实无同框，但有叠加缺陷，检测器同样查不到）、K（干净）。
- 结论：检测器能抓"深色格线"这个主形态（存量 144/1384 命中），但对**浅色/过渡型分隔**和
  **信息图浮层**不可靠；验收不能只用检测器，必须叠加 1fps 人工复核。

## 4. 对根因修复的含义

只剩两条结构性路线，**都改变已确认的产品决策**，需要你拍板：

1. **逐镜生成**：每个镜头单独出片再拼接。K 臂已证明单格参考 + 单镜提示词是干净的，
   但要把"一组一张故事板、一个视频"改成"一组 N 个镜头、N 段视频再拼"，音频/时长/合成链路都要动。
2. **单镜参考 + 后期合成信息图**：视频只驱动一个连续机位，价格对比图改为后期叠加
   （文字可控、不会镜像错乱）。代价是组内只保留一个机位，信息图镜头不再由模型生成。

在这两条落地前，工程防线（检测 + 换 seed 重试 1 次 + 组级 hold + 页面可见）仍可按已批准方案实现，
但它只能"发现并暂停"，不能修好画面。
