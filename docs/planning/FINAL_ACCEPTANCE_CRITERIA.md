## 5. 文案、语言与真实配音门禁

- [ ] 文案只允许粘贴输入，并按项目语言对应的版本化标点规则确定性切句。
- [ ] 分句规则版本 `punctuation-v3`：句末终止符后的闭引号/闭括号归属前一句，不产生孤立引号句；拉丁语系超过约 35 词或 180 字符（日文 90 字符、韩文 75 字符）的句子按从句边界（`—`/`–`、`;`、`:`、`…`、`,`，含全角变体）确定性递归均分，不做句中硬切；分句保持无损与确定性。
- [ ] 纯标点或分隔线行（如 `---`）作为非视觉分隔句保留在冻结文案与前置导演切段中，但不提交 TTS、不进入实测时间轴、配音分组、权威句子表、合成与 SRT；逐句配音完成判定只覆盖非分隔句。
- [ ] 确认配音前的预检返回并展示逐句分句、分隔句标记与估算时长；估算仅用于冻结前提示，不写入权威存储、不参与任何生产计算；估算仍可能超过 15 秒的句子在页面高亮警告但不阻止确认。
- [ ] 首期只接受 `en-US`、`ja-JP`、`ko-KR`、`es-ES`、`fr-FR`、`pt-BR`，且一个项目只能选择一种语言。
- [ ] 不支持语言或检测到混合语言时，在确认配音前阻止生产，不产生 TTS、图片或视频 Provider 调用。
- [ ] 点击确认开始配音后，所有句子都提交真实 CosyVoice 配音；每句都有独立的原文、序号、文本哈希、音频资产和幂等键。
- [ ] 同一次“确认开始配音”用户操作还原子记录项目级前置导演意图；页面断线、刷新或进程重启不会漏掉该意图，也不会创建第二轮 Director Provider 任务。
- [ ] 前置导演与真实配音并行处理，可以覆盖全部冻结句子的多个技术批次，但不创建权威配音分组、不写入任何估算或伪造时长，也不计为最终组级导演完成。
- [ ] 每个返回音频都通过可解码性、媒体格式、静音/空文件和时长质检，并记录实测毫秒时长。
- [ ] 原始和标准化音频均可追溯；失败句不会被占位音、估算时长或伪造音频替代。
- [ ] 任一句配音缺失、哈希不一致、质检未通过或实测时长缺失时，最终组级导演、故事板和视频生产均不能越过门禁；唯一例外是无时间事实的项目级前置导演。
- [ ] 重启或超时恢复只查询或继续同一配音任务，不会自动产生重复 Provider 任务。

- [ ] 第 06 步展示逐句版本化公开状态、失败句序、稳定失败码和恢复建议；只看失败筛选与单句/全部失败句重试仅使用 `allowed_actions`，`OUTPUT_INVALID` 外的句子不开放该重试动作。
- [ ] 配音恢复经过用户二次确认，逐句使用原尝试键调用恢复接口并分别报告受理/失败；重复请求幂等、当前任务不被覆盖、已授权队列重启可恢复、已成功句零重提。GET 轮询具备单在途、过期响应保护和终态停止，成功后对应失败提示消失；HTTP 202 不被当作配音完成。

## 6. 分组、时间轴与导演规划

- [ ] 项目级前置导演输入只来自不可变业务快照和确定性分句；每个前置镜头关联稳定句子身份，全部冻结句子和叙事功能均被覆盖。
- [ ] 前置导演技术批次为多句镜头单元：先由一次全局规划调用通读冻结文案产出分镜大纲（作为确定性产物纳入 canonical 输入），再按确定性分段（非视觉分隔句切段、每单元 3–6 句、硬上限 8 句或约 1200 字符）逐单元执行，最多 4 个单元并发，持续至全部完成；单元镜头覆盖本单元全部句子、只关联本单元句子且上限 min(2×句数, 8)。已确定未产生可用远端结果的失败批次（已收到 2xx 但被本地结构解析或输出校验拒绝、已收到 429/5xx 错误状态码）按每单元最多 3 次尝试、5s/15s 退避（429 尊重 Retry-After）、整轮不超过 2×单元数自动重试；预算耗尽、永久性 4xx 或远端未知态停止尚未提交的批次（在途调用完成后落库），且只有用户点击“重新处理”才能创建新一轮运行。项目级前置导演未知态经用户手动免证据恢复，或已确定收到 Provider 响应但被本地明确拒绝后，若 canonical 输入、项目快照、模型、Prompt、参数和逐批请求合同完全一致且已成功批次的回执与结果哈希完整，新运行复用全部已成功批次（并发产生的失败空洞不影响复用）并只对失败或未提交批次继续，保留运行/单元血缘且不覆盖旧运行；相同输入的任一完整性条件不成立时不得提交恢复运行；canonical 输入变化时要求用户明确确认“按新输入重跑”，全部单元使用新输入，不复用旧成功单元、不改变冻结快照。
- [ ] 前置导演内部修订、Provider 回执、输入哈希和结果哈希不可变保留；普通页面只展示当前最新版本。
- [ ] Director Provider 的 2xx 结构解析失败具有细分稳定错误码，并不可变保存 HTTP 状态、Content-Type、请求 ID 的安全回执或存在性、响应字节数、响应 SHA-256、解析阶段和异常类，以及不含业务正文的 finish_reason 与 usage 计数（Provider 返回时）；响应正文不进入诊断、日志或公开错误。
- [ ] 后端按照原句顺序及完整句子的实测时长确定性装组，正常组的实测总时长不超过 15000ms。
- [ ] 前置导演不参与分组。全部配音和实测时间轴完成后，系统按稳定句子身份执行不调用外部 AI 的确定性重映射；相同输入产生相同运行和相同候选血缘。
- [ ] 跨组镜头保留共同来源血缘；超过组级上限 6 的候选由确定性相邻合并规则自动收敛后继续（合并保留全部来源血缘，规则版本与结果随候选存档）；收敛后仍不合法、覆盖缺失、关联冲突或多样性不合格时进入人工处理，不截断、不做无审计合并、不发布伪造成功结果。
- [ ] 如果任一单句实测时长超过 15000ms，该分组被标记为阻止视频生成并跳过：该组不提交 H3、不生成视频，不会自动切句、切音频、缩短文本；其余正常分组的故事板与视频生成入口正常开放；存在被阻止分组时合成与导出不开放。
- [ ] 每个组的 `start_ms`、`end_ms` 和 `target_duration_ms` 可由逐句音频清单重新计算且结果一致。
- [ ] 句子和导演镜头支持多对多关联：一个镜头可覆盖多句，一句可对应多个镜头。
- [ ] 系统不要求词级强制对齐，也不伪造精确句内镜头时间码。
- [ ] 每组导演规划严格包含 1 至 6 个镜头，顺序稳定且每个镜头有明确画面描述。
- [ ] 多事件文案的镜头覆盖不同叙事事件；仅有相同构图微小动作变化的规划不能通过导演结果校验或人工批准。
- [ ] 导演页面默认可编辑镜头核心字段，高级面板可编辑完整结构化字段、句子关联和连续观察例外审批。
- [ ] 点击生成故事板只会批准并提交当时已通过校验的当前导演方案；校验失败时不创建故事板 Provider 任务。

## 7. 故事板生成与版本行为

- [ ] 每组首期只提交一次“整张多格故事板”图片生成任务，不为每格分别发起图片任务，也不自动切格。
- [ ] 故事板任务保存组内镜头、提示词、角色 IP/风格快照、模型、参数、Provider 任务 ID、回执和内容哈希。
- [ ] 生成结果通过可下载、可解码、尺寸、格式和哈希完整性检查。
- [ ] 不因格线或起始画面无法精确稳定复现而错误阻止技术验收；人工仍可决定是否重新生成。
- [ ] 数据合同能表示未来 `SINGLE_PANEL` 资产，但首期没有对应生成、编辑、拼接或公开 API。
- [ ] 编辑镜头描述只改变草稿修订，不改变当前故事板、当前视频或其输入快照。
- [ ] 重新生成故事板创建新版本；只有新版本成功后才原子切换当前指针，失败时旧故事板继续可用。
- [ ] 故事板切换后旧视频仍保持对旧故事板版本的可追溯绑定，不被自动覆盖或删除。
- [ ] 当前和全部历史故事板资产均可查看；合法候选可由用户明确切换，切换不会修改历史版本内容。
- [ ] 批量生产由两个独立手动动作构成：「批量保存最终导演」只从确定性重映射候选播种缺失草稿（不调用外部 AI，已有草稿/已应用的组跳过，校验不通过如实报告），「批量生成故事板」弹出全组勾选框（默认全选，未勾选跳过；已成功组默认跳过，仅勾选「强制重新生图」后生成新版本）。逐组独立幂等创建意图；在途、远端未知态、导演未通过校验的组不提交并列明原因；任何失败不自动重提。

## 8. KineStack H3 组级视频生成

- [ ] 每个配音分组对应一个视频生成任务；系统不存在按单个导演镜头生成视频的业务路径。
- [ ] H3 请求使用多参考图 REF2VA，不提供首帧、尾帧、首尾帧、参考视频或参考音频字段。
- [ ] 参考图顺序确定且不可变：角色 IP 图片在前，当前故事板整图在后；合计 1 至 9 张。
- [ ] 提示词明确绑定每张角色图和故事板的用途，并要求环境声、禁止人物对白和音乐。
- [ ] Provider 请求时长为 `max(3, ceil(target_duration_ms / 1000))` 整数秒；与实测时长余量不足 0.5 秒且未达上限时 +1 秒；始终位于 3 至 15 秒整数范围。
- [ ] 组内实测时长不足 3 秒时仍请求 3 秒，合成时裁剪到精确组时长。
- [ ] 项目画幅被准确映射为 `16:9` 或 `9:16`，输出采用当前模型/工作流原生分辨率和 24fps。
- [ ] 每个任务保存角色图片、故事板版本、应用中的镜头修订、提示词、时长、画幅、Seed、模型、工作流和 Manifest 快照。
