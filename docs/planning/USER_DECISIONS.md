## 1. 项目与技术基线

1. 当前目录按全新项目实施，不从旧项目迁移业务数据，也不为旧 Schema、旧合同或旧 API 建设兼容层。
2. 数据库、对象存储、任务编排、部署环境、AI 服务和配音调用可以参考相邻的 `D:\AAA-project\TubeFlow AI`，但本项目建立独立领域模型。
3. 后端基础技术方向为 FastAPI/Python、PostgreSQL、Temporal、MinIO、FFmpeg/ffprobe，以及 Provider 适配器。
4. PostgreSQL 是权威业务状态；媒体字节进入对象存储；Temporal 只负责编排，不替代业务状态。
5. 所有外部 AI 生成均由明确的用户操作触发。用户点击“确认开始配音”时，同时授权并自动创建真实配音任务与项目级前置导演任务；前置导演按冻结文案持续处理全部技术批次，直至全部完成、遇到需人工裁决的失败或自动重试预算耗尽。同一次授权运行内部，对已确定未产生可用远端结果的失败批次（已收到 Provider 2xx 响应但被本地结构解析或输出校验拒绝、已收到 Provider 429/5xx 错误状态码）按固定预算自动退避重试；该重试属于同一次用户授权的内部恢复，不构成新一轮 Provider 提交。无响应的超时/连接错误仍归入远端未知态，任何情形都不得自动重提。页面刷新、API 重试、Worker 重启和 Temporal 重放不得创建第二轮 Provider 提交；用户可以通过明确的“重新处理”按钮手动创建新一轮前置导演任务。
6. 正式页面和 API 使用同一来源、同一局域网 HTTP 地址与端口；浏览器只访问这一单一入口，不另设跨域前端生产入口。

## 3. 频道与项目配置

1. 频道来源信息首期只保存频道 URL，不解析频道名称、简介、视频或外部频道数据。此外频道可另存用户自定义显示名称（2026-09-04 确认）：最长 30 字、允许重名、可清空；未设置或清空时页面回退为自动编号名“频道 NN”。显示名称仅为展示元数据，不进入项目快照，修改不影响任何已有草稿或已冻结项目。
2. 每个频道拥有共享角色资产库；角色图片上传后形成不可变版本，同一频道下多个项目可以引用同一资产版本，不做角色图片 AI 生成或图片编辑。
3. 同一项目允许从所属频道角色资产库选择 1 至 8 张当前生效的角色 IP 图片；与一张故事板整图合计不得超过 KineStack H3 的 9 张参考图上限。
4. 项目支持填写画面风格，并将其纳入项目快照和故事板/视频生成输入。
5. 项目级画幅只允许选择 `16:9` 或 `9:16`。
6. 项目可保存“期望目标时长”，但它只是展示与参考值，不参与配音分组、视频时长或合成时间轴计算。
7. 项目创建和生产使用业务项目快照。确认开始配音时，文案、角色 IP、画面风格、音色、语言和画幅全部冻结。
8. 确认配音后，上述内容只能作为资产查看，不能再编辑；如需改变，必须创建新项目。
9. 项目标题是可修改的管理元数据，不进入不可变业务项目快照；确认配音后仍可改名，改名不触发重新配音、重新生成或版本切换。
10. 期望目标时长为可选值，后端按整数秒存储，页面以 `mm:ss` 输入和展示；它不参与任何切句、分组、视频请求时长、合成或字幕计算。
11. 新项目先保存为草稿，再进入十一阶段生产页面：项目配置、文案、角色 IP、画面风格、配音设置、配音与时间线、导演与故事板、分组视频与预览、合成与导出、封面、简介；「封面」阶段在确认配音冻结后开放（2026-09-20 §18），「简介」阶段在 STEP 09 当前合成与最终 SRT 可用后开放（2026-10-26 §36）。
12. 冻结前的可编辑配置采用防抖自动保存；页面必须显示保存中、已保存或保存失败，未确认保存成功不得执行确认配音冻结。
13. 每个频道必须设置且只能设置一个默认公共音色；频道未设置默认音色时不能创建项目。
14. 新项目默认继承创建时该频道的默认音色，但用户可以在确认配音冻结前为项目改选其他兼容音色。频道以后修改默认音色只影响未来新建项目，不改写任何已有草稿或已冻结项目。
15. 如果频道默认音色不支持新项目选择的语言，系统不得自动替换；用户必须在创建项目前手动选择一个支持该语言的公共音色。

7. 确认开始配音后，文案和音色不可再修改。

## 5. 分句、分组与导演规划

1. 时间事实只来自真实逐句配音，不使用文案长度估算、期望时长、占位音频或模型预测时长。
2. 用户点击“确认开始配音”并形成不可变业务快照后，系统在真实配音进行的同时，自动调用真实 Director Provider 生成项目级前置导演方案；该方案只关联冻结句子及其稳定身份，不创建配音分组，也不包含或伪造任何毫秒时间码。
3. 前置导演必须覆盖全部冻结句子和叙事功能。长文案拆为连续技术批次处理；技术批次是“多句镜头单元”：先由一次全局规划调用通读冻结文案产出分镜大纲（作为确定性产物纳入 canonical 输入），再按非视觉分隔句切段、每单元 3–6 句（硬上限 8 句或约 1200 字符）逐单元设计镜头；单元内每句至少被一个镜头覆盖，镜头上限 min(2×句数, 8) 且只关联本单元句子；上下文窗口为相邻单元 ±3 句并保留全局开头 16 句。这些批次属于同一次用户授权的前置导演运行，最多 4 个单元并发处理（并发度可由环境变量配置，自动重试占用并发槽），遇到明确失败按 §1.5 的分类有界自动重试；仅在自动重试预算耗尽、永久性 4xx 失败或远端未知态时停止尚未提交的批次（在途调用完成后落库），不自动降级，远端未知态不自动重提。
4. 页面提供“重新处理”按钮，只有用户点击后才允许创建新一轮前置导演运行。2026-09-08 确认：仅项目级前置导演（`project_director_runs`）的请求级 LLM 调用免除远端未知态的强制外部证据步骤；不改变分组导演、故事板和 H3 等持久远端任务的证据要求，也不得自动重提未知调用。若新旧 canonical 输入、项目快照、模型、Prompt、参数和逐批请求合同完全一致、已成功批次具有完整回执和结果哈希，新运行复用全部成功批次（允许并发产生的失败空洞），只对失败或未提交批次继续；保留成功结果及运行/单元复用血缘。canonical 输入变化时，必须由用户明确确认“按新输入重跑”，整轮不复用旧单元，不改变冻结项目快照。项目锁下检查并保证同时最多一个未终结运行；有实际在途单元、恢复来源变化或旧未知态历史未解决时拒绝创建。免证据处置、旧未知运行及未知单元终结、新运行与出站记录在同一事务中写入，并记录 `manual_evidence_waived`、操作者、时间、来源/新运行及输入哈希；不得伪造“远端未受理”的证据。数据库内部保留不可变修订、调用回执和输入血缘；普通页面只展示当前最新版本。
5. 后端按完整句子的实测配音时长顺序装组，正常情况下每组总配音时长不得超过 15 秒；前置导演结果不得参与或改变配音分组。
6. 全部真实配音、技术质检和实测时间轴完成后，系统不再调用外部 AI，而是按稳定句子身份把当前前置导演方案确定性重映射为最终组级导演候选。
7. 跨最终组的前置镜头只允许产生带共同来源血缘的确定性延续候选，不自动改写创意内容。映射后超过组级上限 6 个镜头时，由确定性相邻合并规则自动收敛至不超过 6 个镜头（保留全部来源血缘，规则版本与结果随候选存档，见 §24）；收敛后仍不合法、句子覆盖不全、关联冲突或叙事多样性未通过时必须进入人工处理，不得自动截断、不得无审计处理、不得伪造成功。（2026-10-14 修订，见 §24）（计时无解合并兜底 2026-10-16 修订，见 §26）
8. 一个镜头可以覆盖多句话，一句话也可以拆成多个镜头；句子与镜头只建立多对多语义关系，不要求词级强制对齐或精确句内镜头时间码。
9. 每组的精确开始、结束和目标时长由组内完整句子的实测配音决定。
10. 如果单句实测配音超过 15 秒，该配音分组被标记为阻止视频生成并跳过：该组不生成故事板、不提交 H3、不生成视频，不自动拆句、切音频、延长视频或修改文案；其余正常分组的故事板与视频生成不受影响，可继续完成；存在被阻止分组时允许合成：被阻止分组及其句子从成片画面、配音音频与 SRT 字幕中整体排除，剩余内容按连续重排的精确时间轴合成，第 09 步页面如实展示被跳过的分组与时长；被阻止组的既有资产继续保留；前置导演仍可查看和重新处理。
11. 每个最终配音组由导演规划 1 至 6 个镜头，最多生成 6 格故事板。（2026-10-14 修订，见 §24）
12. 导演规划的不同镜头应表达不同叙事事件；同一构图中的细小动作变化不能替代真正的镜头规划。相邻关键画面除明确批准的连续观察外，至少改变两个有效叙事或构图维度。
13. 导演页面默认展示当前最新版本和每个镜头的核心字段，完整结构化字段、句子关联和连续观察例外审批放入高级面板；历史修订保留在数据库中但不作为普通页面版本列表展示。
14. 用户点击“生成故事板”时，视为批准当时已经通过导演规则校验的当前最终组级导演方案；校验未通过时必须阻止生成并保留可修改草稿，不再增加独立的重复批准步骤。
15. Director Provider 返回 2xx 但结构解析失败时，失败单元必须保存不含业务正文的安全诊断，包括 HTTP 状态、Content-Type、请求 ID 的安全回执或存在性、响应字节数、响应 SHA-256、解析阶段和异常类，以及不含业务正文的 finish_reason 与 usage 计数（Provider 返回时）；不得在该诊断、日志或公开错误中保存 Provider 响应正文。
16. 前置导演自动重试预算：每批次最多 3 次尝试，退避间隔 5s/15s（第 1 次失败后等 5s、第 2 次失败后等 15s，第 3 次失败即终态；429 响应尊重 Retry-After），单轮运行自动重试总量不超过 2×批次数；预算耗尽后运行置 FAILED 并展示真实失败码，保留人工“重新处理”入口与前缀复用规则。
17. 前置导演运行页面展示真实失败码、失败批次号和自动重试进度（如“自动重试中 n/3”），并发运行期间展示已成功数、在途数与总批次数；不以笼统文案掩盖具体失败原因。
18. 分句规则升级为 `punctuation-v3`：句末终止符后的闭引号/闭括号归属前一句，不产生孤立引号句；拉丁语系超过约 35 词或 180 字符（日文 90 字符、韩文 75 字符）的句子按从句边界（`—`/`–` → `;` → `:` → `…` → `,`，含全角变体）确定性递归均分，不做句中硬切；分句保持无损与确定性，规则版本随快照存档。
19. 纯标点或分隔线行（如 `---`）作为非视觉分隔句保留在冻结文案中，继续供前置导演切段；但不提交配音、不进入实测时间轴、配音分组、合成与 SRT 字幕，也不计入逐句真实配音完成判定。
20. 确认配音前的预检展示逐句分句结果与估算时长；估算仅为冻结前提示，不是时间事实，不写入权威存储、不参与任何生产计算；估算仍可能超过 15 秒的句子仅警告高亮，不阻止确认。
21. 分句规则升级改变权威分句结构，已冻结旧项目在前置导演、故事板、H3 与合成链路会因快照逐句比对失败而不可用；用户确认作废旧项目、以 v3 规则重新导入文案新建项目，不建设旧数据兼容层。

## 6. 故事板

1. 首期由图片模型一次直接生成整张多格故事板，不先生成单格图片再拼接。
2. 数据结构为未来的单格生成方式预留资产类型或关联位置，但首期不实现单格生成、自动切格或单格编辑接口。
3. 接受整张网格的格线、切格和视觉连续性存在一定不稳定，不把首帧必须精确对应某一格设为质量门禁。
4. 每组保存镜头描述、镜头顺序、整张故事板提示词、使用的角色 IP/风格快照、模型参数和故事板整图。
5. 修改单个镜头描述只产生草稿，不影响当前故事板或当前视频。
6. 只有用户点击“重新生成该组故事板”且新故事板成功后，才切换当前故事板版本；失败继续保留旧版本。
7. 故事板重新生成后，旧视频仍绑定旧故事板，直到用户手动生成并选用新视频。
8. 当前及全部历史故事板资产均可查看；历史版本保持不可变，合法候选版本可由用户明确切换为当前版本。
9. 故事板整图生成 Provider 为 grsai（模型 gpt-image-2，国内直连 https://grsai.dakka.com.cn），与前置导演复用同一平台密钥；角色参考图先经 grsai 文件服务上传换取公网 URL 后随任务提交。故事板提交在 connect 阶段失败（TCP/TLS/DNS 未建立，可证明未送达远端）时落为终态 FAILED，允许用户手动重新提交；发送后不确定（读取超时、5xx 等）仍归入远端未知态，只能对账恢复，任何情形都不得自动重提。
10. 故事板支持项目级批量生产，由两个独立手动动作构成：先点「批量保存最终导演」（仅从确定性重映射候选播种缺失的草稿，不调用外部 AI；已有草稿或已应用方案的组跳过；校验不通过的组如实报告为需人工修正），再点「批量生成故事板」。批量生成弹出分组选择框，默认全部勾选，未勾选的组跳过；已有成功故事板的组默认跳过，只有勾选「强制重新生图」后才重新生成新版本（旧版本不可变保留）。每次批量点击是一次新的用户授权，逐组创建独立生成意图与幂等键；在途、远端未知态或导演未通过校验的组不提交并逐组列明原因。批量并发上限默认 20（可配置）；Provider 429 属明确拒绝，落终态 FAILED 且不自动重提，由用户手动重试。

11. 故事板生图提示词按组内镜头数确定性声明网格行列布局，阅读顺序行优先（从左到右、从上到下）：16:9 为 1×1、1×2、1×3、2×2、2×3、2×3（6 格），9:16 转置为 1×1、2×1、3×1、2×2、3×2、3×2（6 格）；5 格时第 6 格在提示词中明确要求纯黑留空，6 格时整格全用、不设留黑（2026-10-14 修订，见 §24）。提示词只包含镜头序号与视觉字段（场景、景别、机位、动作结果、画面描述、角标），不含句子 ID 与叙事功能；角色参考图按上传顺序在提示词中全局绑定（参考图 1…N，各格角色外观保持一致）；角标文本维持 `SHOT n · 0.0s–3.0s` 全文不变，仍由图像模型绘字（§7.19 路线不变）。
12. 故事板生图请求采用 grsai 文档化参数：`aspectRatio` 取官方 1K 像素档（16:9→`1672x941`，9:16→`941x1672`），`quality` 默认 `high`（环境变量可配 `auto`/`low`/`medium`/`high`），模型维持 `gpt-image-2`；不再发送旧 `size` 字段。

## 7. 视频生成

1. 视频生成调用和异步处理逻辑参考 `D:\AAA-project\KineStack`，不复制其页面和业务领域模型。
2. 用户后续提供三台实际视频生成机器的节点地址和连接信息；本项目只需实现兼容的调用适配器和三节点配置能力。
3. 当前本地测试中的 MiniMax H3 在中国部署并使用，许可证问题不属于本地实施阻塞项；正式全球上线前由用户取得 MiniMax H3 自部署正式授权。
4. 视频使用 KineStack 的多参考图 REF2VA 能力，不使用首帧、尾帧、首尾帧组合、参考视频或参考音频输入。
5. 视频生产单位是“配音分组”，不是单个导演镜头。每组故事板生成一个视频。
6. 每组视频输入为：有序角色 IP 图片、该组整张多格故事板、组级视频提示词、目标时长、项目画幅，以及模型/工作流版本快照。
7. KineStack 参考图总上限为 9 张，故事板固定占用 1 张。
8. 视频节点请求时长为整数秒：`max(3, ceil(组内实测配音时长秒数))`；H3 实际产出可能略短于请求值，因此当请求值与实测时长的余量不足 0.5 秒且未达上限时 +1 秒；请求值不得超过 15 秒。
9. 一组视频的 Provider 请求时长最低为 3 秒；最终合成时裁剪到组内精确配音时长。
10. 接受视频起始画面不能稳定复现故事板第一格，不建设首帧一致性强制门禁。
11. 原始 H3 MP4 按模型原生规格永久保存，不覆盖、不强制升级到 1080p。
12. H3 原生音轨作为环境声保留；正式配音是纯人声 TTS。视频提示词应要求环境声但禁止人物对白和音乐，合成时把 TTS 叠加到 H3 环境声上。
13. 当前及全部历史组视频均可查看和播放；该组首次成功归档且尚无当前视频时，系统自动将本次归档设为当前视频；其后重新生成得到的合法候选版本由用户明确切换为当前版本，未选择的候选和旧版本不得被覆盖。
14. 普通用户只查看 H3 服务总体可用或不可用状态，不查看单节点地址、Token、并发明细或其他内部信息；远端等待与疑似卡死的版本化公共状态及已等待时长属于用户可见的生产状态，不属于节点内部信息。
15. H3 总体可用的判定为：30 秒内至少一台已启用且处于 `READY` 的节点完成成功心跳，并与当前模型、工作流及 Manifest 配置完整兼容；节点即使并发已满仍属于总体可用。配置缺失、查询异常、心跳过期或不兼容时必须 fail-closed 为不可用。
16. 组级视频支持项目级批量生产：用户点击一次「批量生成组级视频」视为一次明确授权，弹出分组勾选框（默认勾选可生成组），对每个勾选组逐组创建独立 H3 意图与独立幂等键；执行并发由既有节点槽位调度决定，不另设批量并发配置。被阻止分组、已有当前视频且未勾选「强制重新生成」的分组、在途或远端未知态的分组不提交并逐组列明原因；单组失败不中断批次、不自动重试或重提；强制重新生成只创建新版本，旧版本不可变保留。

17. 组级视频提示词由独立 LLM 编译器生成（新配置组 `video_prompt_provider_*`，当前指向 DeepSeek `deepseek-v4-flash`）：以 KineStack `minimax-h3-structured-v6` 模板为底本，删除台词/旁白规则体系并强制禁止人物对白与音乐、保留自然环境声，保留 `subject_definitions`/`summary`/`retention_analysis`/`detailed_description`/`overall_soundscape`/`non_diegetic_music` 六段结构，输出统一英文。编译在视频生成意图创建时同步执行（该动作为用户手动触发）；编译失败经一次修复重试仍失败则意图显式失败并告知原因，不降级回旧提示词。实机 A/B 结论（2026-09-02，同组对照）：`tubeflow_enhanced_v1`（指令侧锚定网格标签）复现多格同框、已证伪；`kinestack_v6_port` 与 `tubeflow_storyboard_v2` 均产出连续全帧视频；定稿默认模板为 `tubeflow_storyboard_v2`，`kinestack_v6_port` 保留为对照版本，证伪版本代码保留但不再启用。（2026-10-16 修订：默认模板升级为 tubeflow_storyboard_v3，v2 保留对照，见 §26）
18. 视频提示词的镜头节拍采用硬约束时间轴：每个分镜的秒数区间从句级实测配音时长推导，`detailed_description` 逐镜成块，`[Shot 1]` 直接开场，Shot 2 起以 `At mm:ss.mmm, cut to` 绝对切镜点起笔（时刻=该镜实测区间起点）；提示词输出文本必须包含：故事板正面定义句（逐格独立时间镜头而非合成图）、格子阅读顺序（从左到右、从上到下）、量化运镜、末尾一致性清单（Maintain…）与反网格负规则（No storyboard grid, panel borders, split screen, text…）；`overall_soundscape` 由 LLM 按场景撰写，`non_diegetic_music` 固定 N/A；`subject_definitions` 采用角色位置绑定句，不新增角色名称/外观文本字段；`visual_asset_bindings` 行由代码确定性拼装插入；格式锚定示例由真实成功案例改造（剥离音乐内容）。（v3 合同细节 2026-10-16 修订，见 §26）
19. 故事板多格图每格左上角印 `SHOT n · 0.0s–3.0s` 英文角标（0.1 秒精度，与视频提示词节拍逐字一致）；采用在生图提示词中要求图像模型绘字的路线，若实测失败率过高再评估代码后处理叠加。
20. 提示词编译器只影响新建的视频生成尝试，不回填既有项目；画面级多格同框质检兜底另行立项。（2026-10-16 修订：画面级质检兜底已由 §26 立项实施，范围为均匀黑区检测；提示词编译器不回填既有项目的规则不变，见 §26）
21. 组视频远端等待观测（2026-09-03）：每次远端状态查询后持久化该尝试的最近远端状态与状态变更时间；节点身份、原始远端状态与槽位占用只进入服务端日志和数据库，不向普通用户暴露（§7.14 边界不变）；普通用户仅可见版本化公共状态（`waiting_remote` / `remote_stalled`）、已等待时长与可执行动作。
22. H3 停滞隔离（2026-09-03）：远端状态超过阈值零变化（ACCEPTED 30 分钟、RUNNING 60 分钟，均可由环境变量配置）判定为 STALLED；STALLED 尝试的槽位保留但不计入节点调度容量；任何情形不自动重提、不自动取消，仅以降低的固定频率（默认 5 分钟，可配置）继续恢复查询；远端到达终态后按既有链路对账、下载与归档。
23. STALLED 期间该组仍视为未决（2026-09-03）：同组不得再创建新视频尝试，须先由用户手动取消；取消能力对所有在途尝试开放（账号所有权校验与页面二次确认），界面默认仅对 STALLED 尝试展示；引擎确认取消后才释放槽位，引擎不可达时不假定成功，由恢复工作流继续；取消与重新生成是两个独立手动动作，不合并为一个按钮。
24. `SUCCEEDED + QC_FAILED` 是等待用户决策的自动化终态（2026-09-03），不再参与 outbox redrive；不因此做历史数据修复。
25. 节点剩余容量相同的平局按“最久未完成任务的节点优先”打散（2026-09-03），由既有审计事件推导，不新增存储；接入远端队列深度信号本期不实施，仅保留扩展位置。2026-09-08 确认将额外的 STALLED 容量公式差异纳入工作包 4：内存仓储对齐现有 SQL，有效可用容量为最大并发减全部占用槽位加 STALLED 槽位数，不在加回前截断为零，仅正容量允许新增认领；容量及历史完成顺序均相同时取最小 `node_id`。

## 8. 预览、合成、字幕与导出

1. 预览按配音分组查看视频，不按单个镜头查看视频片段。
2. 成片按组顺序合成保留分组的多个视频与纯人声音频；存在被阻止分组时将其画面与配音整体排除，剩余内容按连续重排的精确时间轴合成。
3. SRT 按排除被阻止句后的逐句配音实测时长连续重排生成，不按镜头时间生成。
4. 成片采用所选画幅下的模型原生分辨率和帧率，不额外提升到统一高分辨率规格。
5. 导出 ZIP 包含最终视频、SRT 字幕和当前封面图原图（项目尚无当前封面时不含封面；2026-09-20 §18）。
6. ZIP 不永久保存；下载时临时或流式生成，响应完成或中断后清理。
7. 新合成进行中或失败时，旧的当前成片继续可查看、播放和下载；当前及全部历史成片均可查看和播放，合法候选版本可由用户明确切换。
8. 页面允许预览当前或选定历史版本的视频和 SRT 内容；SRT 预览卡提供当前预览字幕的独立 `.srt` 便捷下载（2026-10-17 §28 修订），但唯一正式交付入口仍是临时或流式 ZIP，不提供独立 MP4 或封面图正式下载入口。
9. 最终视频封装为 MP4，视频编码为 H.264，音频编码为 AAC；保持项目画幅对应的模型原生尺寸和 24fps，不执行未经要求的升采样。

## 9. 资产生命周期与删除

1. 项目存在期间，逐句音频、导演规划、故事板、原始视频、合成视频、SRT、Provider 输入/回执、哈希、技术元数据和全部历史版本均永久保留，不设置 TTL。
2. 重新生成创建新版本，不覆盖或删除旧版本。
3. 全部历史资产的元数据均可查看；音频、图片、视频和字幕等可预览媒体均可在所有权与版本绑定校验后播放或预览，合法候选版本可按对应业务规则明确切换。
4. 删除项目代表不可恢复地物理清理项目专属业务数据和媒体对象。
5. 删除采用二次确认和异步清理；根据数据库记录的精确对象键逐个删除，不使用路径猜测、通配符或前缀递归删除。
6. 全局公共音色库不随项目删除。频道共享角色资产库及其不可变版本独立于单个项目存在；项目删除只移除该项目的引用和项目专属资产，仍被同频道其他项目引用的角色资产不得物理删除。
7. 删除完成后只允许保留不含文案、提示词、媒体或个人内容的最小审计墓碑。
8. 页面发起不可恢复删除前，用户必须准确输入当前项目标题作为二次确认；后端仍按项目 ID 和账号所有权执行删除，不以标题作为资源定位依据。（实现备注 2026-10-20：确认值经 `X-Confirm-Project-Title-B64` 以 UTF-8 base64 传输，因为浏览器禁止非 ISO-8859-1 的请求头值；明文头保留兼容，匹配规则不变。）
9. 删除请求签发与账号和项目绑定的认证加密回执，回执有效期恰好为 10 分钟；项目物理删除后只能凭有效回执查询最终 `DELETED`。最小审计墓碑不保留 `owner_id`，篡改、过期、跨项目或跨账号回执必须 fail-closed。

## 10. 页面状态与公开 API 合同

1. 后端提供权威 `workflow_summary`，以真实任务和资产计数表示各阶段完成情况、当前阻塞原因和可执行动作；页面不得生成或展示没有权威依据的虚假完成百分比。
2. 面向页面的异步任务合同统一提供 `public_status`、`message` 和 `allowed_actions`；领域内部状态可以保留，但页面行为不得依赖未版本化的 Provider 或工作流专有状态。
3. `allowed_actions` 是当前账号在当前资源状态下可安全执行的动作集合；未知远端状态只能提供查询、对账或已确认的恢复动作，不得提供会创建第二个 Provider 任务的普通重试动作。
4. 页面生产数据全部来自真实 API 和 PostgreSQL 权威状态；不得使用 `localStorage`、内置演示数据、手工回填时长、伪造成功状态或静默本地回退代替生产调用。
5. 页面必须显示后端返回的稳定业务错误和恢复建议；网络失败、权限失败、版本冲突、未知远端状态和 Provider 失败不得被合并为伪造成功或无说明的通用失败。
