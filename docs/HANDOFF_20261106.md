## 5. 操作要点（踩过的坑，别再踩）

**机器与库**

- 部署机 `edy@192.168.110.200`；项目 `/home/edy/tubeflowai-test`；容器前缀 `tubeflowai-test-`。
- **`edy` 在 docker 组，不需要 sudo**。命令行里写 sudo 密码会触发 `SENSITIVE_APPROVAL=TIMED_OUT` 闸门。
- SSH 一律用仓库自带的 askpass（别在命令里写密码）：
  `export SSH_ASKPASS="$PWD/tmp/ssh-edy/askpass_local.sh" SSH_ASKPASS_REQUIRE=force`，`-o UserKnownHostsFile="$PWD/tmp/ssh-edy/known_hosts"`，命令走 `'bash -s' <<'EOS' … EOS`。
- **测试库与业务库不是同一个 Postgres**：`tubeflowtest` 在容器 `tubeflow-contract-pg`（角色 `postgres`，宿主 `127.0.0.1:55432`）；业务库 `tubeflow` 在容器 `tubeflowai-test-postgres-1`（角色 `tubeflow`）。集成测试只碰前者。
- 集成测试用 SSH 隧道 `-L 127.0.0.1:554xx:127.0.0.1:55432` + `TUBEFLOW_TEST_POSTGRES_URL=postgresql+psycopg://postgres@127.0.0.1:554xx/tubeflowtest`；554xx 换一个没占用的端口。

**工具层的两个怪现象**

- **显示层会改写某些标识**（容器名会被换成随机 slug 之类）。别相信眼前看到的字符串——用 `grep -c` 之类**只输出数字**的办法判定文件真实内容。
- 远程 heredoc 里用 `docker exec -i` 会**吞掉脚本剩余内容**（stdin 被抢），改用不带 `-i` 的形式，或先把脚本落盘再 `docker cp`。

**流程**

- 部署：`git archive` → 部署机独立 build 目录 → `docker build` → 改 compose 三处 image → `up -d --no-build`；**不要在部署机源码树 build**（那是旧版）。
- 部署前按 `USER_DECISIONS` §52 查两项（`project_director_units` 的 LEASED/SUBMITTING 数 + Temporal pending `advance_project_director`），为 0 才重启。
