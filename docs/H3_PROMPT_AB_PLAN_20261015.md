## 1. 实验变量与候选模板

每个变量对应一个新增的版本化策略（纯追加，只影响新尝试，不回填既有资产）：

| 变量 | 来源差异 | 候选改动（相对 v2 的唯一变化） | 依据 |
|---|---|---|---|
| V1 | D1 标签写法 | 裸 `Picture N` / `(S1)` 改为 `<Picture N>` / `<Subject N>`，校验器同步 | 官方 ref-en.txt §2；drama-skills minimax-h3.md；KineStack `translate_references`（`h3_workflows.py:222-227`）三来源一致 |
| V2 | D3 retention 分级 | 故事板主体保留强度降为 `partially_preserved`，条目附 `(appears in [Shot n])` 镜次 | 官方 ref-en.txt §4 四级词汇与条目格式 |
| V3 | D6 对齐句 | `subject_definitions` 之前加首行对齐句，把格子 i 逐字钉到秒数（句式仿官方 I2VA/FL2VA 首行指令） | drama-skills 容器实测（逐切关键帧+对齐句切点 ±0.04s）；官方 base-en.txt §2.1 |

单变量原则：每版只改一处，不混合；其余规则逐字保持 v2。

本轮不测"可直接借鉴"项（D2 映射声明、D4 任务前缀、D5 篇幅带、D7 嘴部措辞、可生成性规则），避免污染变量；它们可另立一个候选版本在后续轮次评估。

## 2. 对照设计（沿用 §7.17 的 2026-09-02 同组对照先例）

- 同一配音分组、同一故事板当前版本、同一 seed（`generation.seed` 按生成固定，新尝试复用同一种子；KineStack 在收到显式 seed 时不另行派生）。
- 选组：1 个短组（≤6 秒、镜头少）+ 1 个长组（≥10 秒、切点多），沿用 §18.5 长短各一的选组思路；优先选当前已出片但质量中等、有可见改进空间的组。选组名单在首次报批时逐组列明。
- 每臂：baseline（v2 同组重跑）×1 + 候选 ×1；候选首次出现结构性失败（校验不过/网格泄漏）时可追加 1 次，封顶见 §4。
- 既有资产不受影响：新尝试创建不可变新版本，仅在用户确认改善后才切换当前指针。

## 3. 度量与判定（预注册，先定尺子再跑）

统一度量（两臂同测）：

1. 结构合规：编译输出必须通过现有校验器全部断言，否则该臂记失败、不提交 H3。
2. 切点精度（V3 主指标）：ffprobe 场景切变检测对照 `shot_plan` 切点，记录逐切点误差；v2 臂同测作当期基线。
3. 网格/文字泄漏（V2 风险指标）：抽帧人工核对格子边框、面板编号文字、分屏构图。
4. 身份与风格保持（V1/V2 指标）：逐镜人工 checklist 核对角色身份、服装、场景连续性，以故事板格子为参照。
5. 技术基线：ffprobe 记录分辨率、帧率、时长、码率；不做超出观测的主观画质断言。

判定规则：

- 候选臂出现多格同框/网格泄漏 → 该变量证伪，弃用（对照 §7.17 对 `tubeflow_enhanced_v1` 的处理）。
- 候选臂编译含一次修复后仍不过硬校验 → 证伪，不消耗 H3 额度。
- 与 v2 臂无可见差异 → 不采用，保留 v2 默认。
- 仅当"可见改善且无回归"时才建议采用；是否采用由用户决定，采用后同步更新 `USER_DECISIONS.md` 与验收文档。

## 4. 调用预算估算（申请额度，逐次报批）

| 类型 | 用途 | 估算 |
|---|---|---|
| DeepSeek `deepseek-v4-flash` 文本编译 | 每尝试 1 次编译 + 至多 1 次修复 | 3 变量 × 2 组 × 2 臂 × ≤2 = **≤24 次** |
| KineStack H3 视频提交 | 每臂 1 次起；候选结构失败可追加 1 次 | 3 变量 × 2 组 × (1 baseline + ≤2 候选) = **≤18 次封顶** |

- 失败或结果未知的已提交尝试占额度，不自动追加（§18.5 同口径）。
- 预计耗时：短组单次分钟级、长组单次十几分钟级，实际以队列为准，未知记未知。
- 每次提交前逐次报批：对象（项目/组/故事板版本）、模板版本、seed、预计时长与耗时。
- 省额备选：v2 基线臂可改为复用该组当前指针视频（不同时期/节点状态的对照强度略降），H3 额度降为 ≤12 次；取舍由用户在首次报批时拍板。

## 5. 实施前置（零真实调用，可先做的部分）

1. 新增 3 个策略枚举与候选模板文本（纯追加式改动，默认策略不变）。
2. 校验器扩展：尖括号标签口径、retention 分级词汇、对齐句断言——仅对对应策略生效，v2 校验口径不变。
3. 全部单元/契约测试使用假 Provider；`pytest`、`ruff`、`mypy` 通过后才进入真实调用报批环节。
4. 上述代码改动属于实施，需用户明确批准后才动手；本方案本身不含任何代码变更。

## 6. 风险与边界

- 回归风险（格子复刻、身份漂移、切点漂移）由 §3 判定规则覆盖；版本化模板可即时停用，证伪版本代码保留不启用（§7.17 惯例）。
- 每次真实提交在 `runtime/operations/` 留记录：对象、模板版本、seed、回执哈希、费用（未知记未知）。
- 本实验只动提示词层，不触碰 §18.1 已确认的边界（保留主模型、原生分辨率与 24fps、不启用放大或首帧模式）。
- 若实验期间 KineStack 工作流/模型版本变化，本方案的对照前提（同种子可比性）需重新确认后再继续。
