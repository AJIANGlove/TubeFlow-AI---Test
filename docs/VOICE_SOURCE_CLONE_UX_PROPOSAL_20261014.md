## 0. 关键结论（TL;DR）

1. **核心病根**：把"两个层级、四个概念"平铺在同一屏——配音源（父级）、当前默认音色（子级）、音色库（资源清单）、克隆表单（创建动作），四者无分组、无标题、无主次，用户必须先读三个标签才能建立"源 → 音色"的心智映射。
2. **流程重构**：改为两级信息架构——「① 选择配音源（2 张平铺卡）→ ② 进入源内工作区（当前使用状态条 + 使用已有音色 + 上传音频克隆）」，一屏只做一个决策。
3. **顺序倒置**：当前实现要求"该源已有默认音色才允许切换到该源"（否则拦截并回滚，【实现核对】），与"先选源、再选音色"的自然顺序相反 → 改为"先进入、后就绪引导"。
4. **默认音色语义**（建议定义）：**试听 = 零门槛直接播放；"成为默认" = 必须显式确认**；任一时刻唯一「使用中」；克隆成功不自动变更默认。
5. **标识体系**：来源徽标 + 类型徽标（克隆/公共）+「频道共享」+「使用中」；名称 = 唯一标识（必填、校验），备注 = 补充说明。
6. **反馈体系**：把"全页冻结 + 4.2 秒自动消失的提示"升级为"表单局部进度 + 就近错误 + 常驻结果卡"；另发现现有克隆结果卡会被随后的整页重渲染重置（【实现核对】），实际只有短暂提示承载结果。
7. **优先级总览**：P0 共 6 项（流程 3 + 默认语义 1 + 反馈 1 + 删除防护 1），P1 共 9 项，P2 共 6 项。
8. **决策状态**（2026-10-14）：附录 A 的 8 项假设已全部确认（A1–A7 见附录 A；A8＝**方案 A**，见附录 C）；P0 清单已落地前端（实施记录另见 `docs/VOICE_PANEL_P0_IMPLEMENTATION_20261014.md`）。

## 2. 操作流程重构（先选源 → 源内选择 / 克隆）

### 2.1 问题诊断（F 组）

| 编号 | 问题诊断 | 优化方案 | 设计理由 | 优先级 |
|------|----------|----------|----------|--------|
| F-01 | **父子层级并列**：配音源（父级选择）与"当前默认音色"（该源的子级属性）同排、同权重、同样式，布局无法表达从属关系（截图：两控件并排于面板首行） | 拆为两级：①「选择配音源」平铺卡片区；② 源视图内以"状态条"呈现「当前使用音色」。子级信息不再与父级选择并列 | 布局结构 = 信息模型的可视化；父子关系必须显性化，否则用户需先读标签、再脑内建模（认知负担的主要来源） | **P0** |
| F-02 | **顺序倒置**：切换到某源时，若该源尚无默认音色会被拦截并回滚（提示「请先在下方选择并设为默认克隆音色」，【实现核对】）。即系统要求"先在列表设默认音色、再回来切源"，与"先选源 → 再选音色"相反；且此刻列表恰被下拉浮层遮挡，操作被割裂 | 改为"**先进入、后就绪引导**"：点击源卡即进入该源视图；未就绪时状态条显示「未设置默认音色 + 引导动作」；"未就绪"不影响查看与管理，仅在"创建项目"入口同步提示限制 | 把系统约束放到**使用点**（创建项目）而非浏览点（切换源）；消除死锁式回滚报错 | **P0** |
| F-03 | **渐进披露缺失**：同屏同时呈现源选择、当前音色、音色库（含试听/设默认/删除）、克隆表单（4 字段），无分组无主次 | 两级渐进披露（① 源 → ② 源内工作区）；源内为"状态条 + 已有音色列表（为主）+ 上传音频克隆入口（为辅，表单默认折叠）" | 每增加一个同屏决策点，扫描时间与出错率非线性上升；90% 高频操作只是"换用某个已有音色"，应为高频路径让路 | **P0** |
| F-04 | **双选项下拉 + 展开遮挡**：仅 2 个选项却需展开才可见全部；展开浮层覆盖下方卡片（截图：卡片名称行被遮挡）；能力差异（是否支持克隆、是否付费）只藏在选项文字的括号里 | 改为 **2 张平铺单选卡**：卡面直接承载「源名 + 能力徽标（支持音频克隆 / 公共音色库 / 付费）+ 当前使用标识」，点击即进入 | 选项少则不应隐藏（避免"展开-阅读-选择"三段成本）；卡片 = 选项 + 说明 + 状态的复合载体，选择依据前置 | P1 |
| F-05 | **「查看源」与「设为生效」未解耦**：下拉 change 即写库（【实现核对】），用户只是"想看看 EL 有哪些音色"也会触发配置变更与拦截报错 | **已确认（2026-10-14，方案 A）并已实施**：源卡切换＝纯查看；「设为频道默认」即生效、跨源自动切换配音源（反馈明示）；方案 B / C 未采用 | 有副作用的动作需要可预期、可解释；"看"与"改"分离是配置类界面的基本纪律 | P1 |

### 2.2 目标信息架构（IA）

```
「配音源与克隆音色」（频道级配置）
├─ ① 选择配音源（平铺单选卡 ×2）
│   ├─ CosyVoice（自有配音机）   ［公共音色库］ ［当前使用?］
│   └─ ElevenLabs（付费 TTS）    ［支持音频克隆］ ［付费］  ［当前使用?］
└─ ② 音色工作区（随所选源切换；标题 = 「{源名} 音色」）
    ├─ 状态条：当前使用 = [音色名] +［来源/类型徽标］+［试听］
    │        ｜ 未设置时 = 引导态（"请选择或克隆一个音色"）
    ├─ 入口 A：使用已有音色（列表为主，常驻）
    │   ├─ 列表头：已有音色 ·「频道共享」· N 个
    │   └─ 条目：名称（主）/ 备注（次）/ 元数据（弱）/ [▶ 试听] /［设为频道默认］/［删除］
    └─ 入口 B：上传音频克隆（仅 ElevenLabs 源提供；默认折叠，点击展开表单）
        ├─ 音色名称* ｜ 备注
        ├─ 源音频*（规则前置提示：格式/大小 ⚠️上限待定）
        └─［上传并克隆］→ 上传中 → 克隆中 → 结果卡（成功 / 部分失败 / 失败+重试）
```

> 已确认（2026-10-14）：① 第二级入口文案采用**「使用已有音色」**（A3）——避免与"源音频"字段混淆；② **仅 ElevenLabs 支持音色克隆**（A2，与 `USER_DECISIONS.md` §23.2 一致）——CosyVoice 源内不提供「上传音频克隆」入口。

### 2.3 主路径（分步操作路径）

以"首次为频道配置 ElevenLabs 源"为例（主线按推荐方案 A 描述；A8 决策点见附录 C）：

| 步骤 | 用户动作 | 系统反馈 | 目标与用户收益 | 为何降低认知负担 |
|------|----------|----------|----------------|------------------|
| S1 选择配音源 | 在两张平铺源卡中点选「ElevenLabs（付费 TTS）」 | 卡片进入选中态；下方区域标题切换为「ElevenLabs 音色」；状态条与两个入口出现 | 一次只做一个决策；能力差异（支持克隆 / 付费）在同一屏可见 | 选项全量可见（仅 2 项，无需展开与记忆）；"源"是后续一切选项的总筛选器，先定源 = 后续内容全部相关 |
| S2 进入源视图，确认当前状态 | 扫视状态条 | 「当前使用：EL-UAT-1 · 克隆 · ElevenLabs · 试听」；未设置时显示引导 | 明确"我在哪个源的范围内操作、当前用的是谁" | 父子层级可视化（源 → 音色），消除"当前默认音色属于哪个源"的歧义 |
| S3A 使用已有音色 | 在列表试听 → 点「设为频道默认」 | 按钮即时反馈（进行中 → 完成）；状态条更新；该卡片获得「使用中」徽标；轻提示确认 | 复用已有资源，零上传成本 | 试听零门槛（无副作用，直接执行）；生效需一次显式确认（有副作用，必须确认）→ 动作成本与后果匹配 |
| S3B 上传音频克隆 | 填写名称 → 选择源音频（即时校验）→ 提交 | 内联校验提示 →「上传中…」（进度）→「克隆中…」→ 结果卡（成功：新卡置顶高亮 + 「设为频道默认」快捷动作；失败：原因 + 重试，输入保留） | 创建新音色全程可见、可恢复 | 系统状态可见（无需猜测"是否在忙"）；失败可行动（错误在触发点就近呈现且不自动消失）；默认不被隐式变更（无意外副作用） |
| S4 收尾 / 离开 | 无（或继续其它操作） | 若未设默认，状态条明确「频道当前仍使用：X」 | 无隐形状态变更 | 系统结果与用户动作一一对应，无需回查记录 |

### 2.4 异常与取消路径

| 编号 | 场景 | 系统处理（设计） | 恢复出口 | 优先级 |
|------|------|------------------|----------|--------|
| E1 | 文件不合规（格式/大小/空文件） | 选择文件后**即时**内联错误；提交按钮保持不可用；文案给出规则与修正建议（格式范围可参照现有 accept 约定；⚠️大小上限待定） | 重新选择文件 | P1 |
| E2 | 名称缺失 / 纯空白 | 失焦即提示「请填写音色名称」；按钮联动不可用 | 修正即消 | P1 |
| E3 | 名称重复（同源同名） | 已确认要求同源唯一（A7）：失焦校验 + 内联提示 + 建议名称，不静默覆盖；后端已有同名拒绝（`cloned_voice_name_conflict`，实现核对） | 改名后重试 | P1 |
| E4 | 克隆失败（部分账号 / 全部账号 / 无可用账号） | 结果卡**常驻**于表单下方，如实列出失败账号与原因，提供「重试」；表单内容保留 | 重试或修改后重试 | **P0** |
| E5 | 提交过程中想取消 / 离开 | 按**同步单请求**处理（A6 已确认）：不提供中止 / 取消；提交期间明确「处理中，请保持页面打开」；失败后表单保留可重试 | 重试（如失败） | P2 |
| E6 | 切换源时存在未提交的克隆表单 | 切换前提示「切换将丢弃未提交的表单」，提供"继续编辑 / 放弃并切换"；切回该源时表单内容保留（同一会话内） | 两种选择均有明确出口 | P1 |
| E7 | 试图删除被保护音色（频道默认 / 被引用） | 按钮禁用 + **可见原因**（不依赖悬停 tooltip），并提供「先去改选默认」直达动作 | 改选默认后再删 | P1 |
| E8 | 切换到尚无默认音色的源 | 不再拦截回滚；正常进入，状态条「未设置」+ 引导（选已有 / 上传克隆）；创建项目入口同步提示未就绪 | 完成引导即恢复 | **P0** |

## 3. 默认音色处理规范

### 3.1 问题诊断（D 组）

| 编号 | 问题诊断 | 优化方案 | 设计理由 | 优先级 |
|------|----------|----------|----------|--------|
| D-01 | **「默认」语义与确认机制未定义**：同屏出现"默认配音源 / 当前默认音色 / 设为默认"三个"默认"，但未定义：试听是否需确认？选取是否即时生效？"默认"作用域是什么（频道 / 项目）？截图：只读框「EL-UAT-1」与卡片按钮「设为默认」的关系需用户自行猜测 | 见 3.2 语义定义：试听零门槛；**生效必须显式确认**；唯一「使用中」；作用域统一为频道并在文案中显式（「频道默认音色」） | 同名不同义的状态词是误操作的温床；单一语义 + 单一确认点 = 行为可预期 | **P0** |
| D-02 | **状态伪装成控件**：当前默认音色以"禁用输入框"（灰底只读框）呈现——既不美观，也诱发无效点击与困惑（"为什么不能改？"） | 改为**状态条**组件：音色名 + 徽标组 + 试听 + 未设置时的引导态；状态展示不再使用输入框外观 | 控件外观 = 交互承诺；状态信息应"可读、可信、可行动"，而不是"看起来坏了" | P1 |
| D-03 | **类型 / 来源标识体系缺失**：卡片未标注音色性质（克隆 / 公共）与来源（ElevenLabs / CosyVoice），尽管副标题声明"频道内共享" | 徽标体系（3.3）：来源 + 类型 + 频道共享 + 使用中 | 标识 = 信任基础；共享资源必须"来源可溯、范围可见、可删性明确" | P1 |
| D-04 | **命名与唯一性规则缺失**：卡片次行格式为"备注 · N 字节"；只读框「EL-UAT-1」与卡片文字风格不一（A1 已确认：只读框 = 当前默认音色名；卡片次行 = 备注 · 大小）；名称字段无格式 / 唯一性提示（【实现核对】仅长度上限） | 名称 = 唯一标识（必填、同源唯一校验、长度与字符提示）；备注 = 补充说明（空则不显示占位）；展示优先级：名称（主）→ 备注（次）→ 元数据（弱） | 命名混乱会让"当前使用"与"列表条目"无法对应，直接影响防误操作 | P1 |
| D-05 | **删除与保护：缺确认、原因不可见**：点击「删除」即执行（**无二次确认**，【实现核对】）；删除是破坏性的（远端音色与源音频一并清理）；被保护时按钮置灰但原因仅在悬停提示中，截图中灰按钮看似"失灵" | ① 删除 = 二次确认弹窗（说明影响范围与不可撤销）→ 成功后轻提示；② 保护原因从悬停提示移到**可见文案**；③ 提供「先去改选默认」直达动作 | 破坏性操作必须高成本触发（确认）+ 充分知情；禁用态必须解释原因（Nielsen #5 错误预防） | **P0** |
| D-06 | **「设为默认」作用域文案不明**：按钮未说明作用域（频道级、影响新建项目）；【实现核对】成功提示中已有"频道默认 / 已有项目不受影响"说明，但按钮本身没说 | 按钮统一为「设为频道默认」；已生效项显示「使用中」禁用态 | 作用域可见 = 影响可预期 | P2 |
| D-07 | **克隆成功 → 默认策略未明示**：克隆成功后不会自动成为默认音色（【实现核对】），但成功反馈未说明"当前默认未变更" | 保持"不自动变更"；成功反馈中提供「设为频道默认」快捷动作，并明示"当前使用音色未变" | 最小惊讶原则：避免"上传即生效"的意外，也避免用户误以为已生效 | P1 |

### 3.2 「默认音色」的语义定义（回答"预置可直接播放"还是"需用户确认"）

**结论：二者不矛盾，建议拆成两个维度分别定义——"播放"零门槛，"生效"必须确认。**

| 维度 | 定义 | 原因 |
|------|------|------|
| **试听（播放）** | 预置 / 克隆音色均为已就绪资源，点击播放按钮**立即播放，无需任何确认** | 无副作用的动作不应设门槛；试听是用户评估音色的核心手段，门槛只会阻碍决策 |
| **生效（设为默认）** | 任一时刻只有一个「使用中」音色；变更必须通过一次**显式动作**（「设为频道默认」）并给出成功反馈；不因浏览、试听、克隆而隐式变更 | 有副作用的动作需要确认点；单一「使用中」标识让"当前到底用谁"永远一目了然 |
| **作用域** | 频道级（页面已声明"频道内共享"）；对已有项目的影响在动作反馈中说明 | 影响范围必须与用户认知一致 |

**状态模型**：

| 状态 | 含义 | 视觉呈现 | 可用动作 |
|------|------|----------|----------|
| 候选音色 | 在列表中、当前未被使用 | 常规卡片 | 试听 / 设为频道默认 / 删除（受保护除外） |
| 使用中 | 频道当前默认音色（全局唯一） | 「使用中」徽标 + 主色强调 | 试听；（重复设默认 / 删除被阻止并说明原因） |
| 未设置 | 该源尚无默认音色 | 状态条引导态 | 选已有音色 / 上传克隆 |

### 3.3 预置 / 克隆音色的区分展示（徽标体系）

| 徽标 | 取值 | 样式建议 | 出现位置 |
|------|------|----------|----------|
| 来源 | CosyVoice / ElevenLabs | 中性描边小标签 | 卡片、状态条 |
| 类型 | 克隆音色 / 公共音色（A2 已确认：仅 EL 提供克隆；CosyVoice 为公共音色库） | 中性描边小标签 | 卡片、状态条 |
| 范围 | 频道共享 | 若列表标题已声明可不在卡片重复 | 列表标题 |
| 状态 | 使用中 | 主色实底、全局唯一 | 状态条、对应卡片 |

> 颜色仅作辅助：徽标以**文字**承载语义，避免"仅颜色编码"（可达性）。

### 3.4 命名与标识规则

| 项目 | 规则建议 |
|------|----------|
| 音色名称 | 必填；建议 2–40 字符；**同源内唯一**（A7 已确认：失焦校验 + 内联提示；后端已有同名拒绝可对接）；拒绝纯空白 / 纯符号；占位提示说明用途（"用于在列表中区分音色"） |
| 备注 | 可选；长度上限与现有一致；卡片次要行展示，**为空则隐藏该行**（不用"无备注"占位） |
| 公共音色名称 | 系统提供、不可编辑（CosyVoice 公共音色库；A2 已确认） |
| 元数据 | 大小、创建时间等弱化展示（次行或悬停），不进入主视觉流 |
| 展示一致性 | "当前使用"状态条与列表条目使用**同一名称 + 同一徽标组**（一处定义，多处复用） |

### 3.5 防误操作清单

1. **「设为频道默认」必须显式点击**；已是当前项时按钮禁用并显示「使用中」。
2. **删除必须二次确认**（含"远端音色与源音频一并清理、不可撤销"说明），确认按钮使用危险样式。
3. **当前默认不可直接删除**：禁用 + 可见原因 +「先去改选默认」直达；删除成功给出明确反馈。
4. **克隆成功不自动设默认**（保持现状），成功反馈提供「设为频道默认」快捷动作。
5. **名称重复提示**在先、建议在后，不静默覆盖。
6. **付费提示**：本次不涉及（A4 已确认）——不新增费用 / 额度相关提示；现有「（付费 TTS）」命名保持。

## 附录 C：A8 详细重述与决策简报（已确认：方案 A）

> 用户反馈（2026-10-14）：A8 暂未理解，需重新详细描述后再确认。
> **决策结果（2026-10-14）**：用户确认采用**方案 A**；P0 实施已按方案 A 落地（见 `docs/VOICE_PANEL_P0_IMPLEMENTATION_20261014.md`）。

### C.1 背景：系统里目前有两层"默认"

每个频道保存两样与配音有关的设置（【实现核对】；对外语义见 `USER_DECISIONS.md` §23.1）：

1. **当前使用的配音源**：CosyVoice 还是 ElevenLabs；
2. **每个源各自记住的默认音色**：两个源各存一份（EL 源记克隆音色、CosyVoice 源记公共音色），切回来时无需重新选择。

由此产生两个可感知的别扭点（F-02）：在音色列表点「设为默认」**并不等于频道开始用它**（若该音色属于另一个源，频道实际使用的仍是原来的源）；而想切换配音源时，如果目标源还没有默认音色，又会被拦截回来先去设置音色（顺序倒置）。

### C.2 待决策的问题

新流程（先选源 → 源内选择 / 克隆音色）中，
**「把某个音色设为频道默认」这一个动作，应该只影响"该源记着什么音色"，还是同时决定"频道真正使用哪个源"？**

### C.3 三个候选方案

以"频道当前使用 CosyVoice 的音色，现在想改用 ElevenLabs 的 EL-UAT-1"为例：

**方案 A（推荐）：「设为频道默认」即生效，跨源自动切换。**

- 操作：进入 ElevenLabs 源视图 → 对 EL-UAT-1 点「设为频道默认」→ 完成。频道配音源自动切换为 ElevenLabs，并明确提示"已将频道配音源切换为 ElevenLabs"。
- 界面：任意时刻全局只有一处「使用中」——源卡上标"当前使用"的源与列表里标"使用中"的音色永远一致。
- 取舍：用户只需理解一个概念（"我用哪个音色，就点它的设为默认"）；代价是不能"为另一个源预先配好音色但先不启用"。

**方案 B：「设置」与「启用」分开（两个动作）。**

- 操作：对 EL-UAT-1 点「设为频道默认」（仅记录到 EL 源）→ 再点该源上的「启用本配音源」→ 完成。
- 界面：需同时表达"本源默认音色"与"频道当前使用源"两种状态；未配置音色时「启用」禁用并引导先设置。
- 取舍：可预先为两个源各配好音色、随时启用切换；代价是用户要分清"设置"和"启用"，跨源生效需两步。

**方案 C：折中——跨源时弹窗询问。**

- 在**当前源**内设默认：直接生效（同方案 A）。
- 在**非当前源**设默认：弹确认——"是否同时将频道配音源切换为 ElevenLabs？［一起切换］［仅记录设置，不切换］"。
- 取舍：默认场景少打扰、跨源时由用户当场决定；代价是多一次确认弹窗，需文案讲清两个选项差别。

### C.4 推荐与理由

推荐**方案 A**：

1. 与目标流程自洽——"先进入某源、再从源内选音色"本身就是明确意图，选择即生效，无需第二个确认动作；
2. 从根上消化 F-02 的顺序倒置：不存在"先设置音色、再切源"的死锁；
3. 全局唯一「使用中」，彻底消除"两层默认"的认知负担；
4. 当前为频道级单配置场景（截图与实现均未见多源预配置需求），A 的代价本期可忽略；将来若出现"预配置 / 频繁切换"需求，可平滑演进为 B / C。

### C.5 若确认方案 A，实施影响面

- 「设为频道默认」提交时同时携带"配音源 + 音色"两个字段（现有接口已支持组合提交，【实现核对】）；
- 源卡「当前使用」标识与状态条「使用中」徽标联动、全局唯一；
- 删除源切换的拦截回滚逻辑，替换为就绪引导（F-02 / E8）；
- 数据模型不变：两源各自的默认音色记录继续保留，仅改变"用户动作 → 字段更新"的绑定方式。
